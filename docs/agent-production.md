# Production rate limiting for gameplay

The gameplay WebSocket currently accepts loopback requests in Vite development. Before exposing it publicly, put usage controls at the WebSocket handshake and at the point where a move triggers Workers AI.

1. **Verify identity before routing.** Hook authentication into `routeAgentRequest` and validate the user’s session on every WebSocket upgrade. With Cloudflare Access, verify the assertion’s signature, issuer, audience and expiry. Use the verified subject and a server-issued session ID to address the Durable Object. Check the browser origin and close sockets when the session expires. [Agents authentication](https://developers.cloudflare.com/agents/runtime/routing/authentication/), [Access JWT verification](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/validating-json/)
2. **Throttle upgrades and decisions.** Add a Workers Rate Limiting binding for connection bursts and another for inference bursts. Key upgrades by user or, before authentication, by client IP. Key inference by the verified user before every `AI.run`, including requests on an already-open socket. Start with 10 upgrades and 30 decisions per minute per user, then tune with play traces. Return HTTP 429 at upgrade or a retry interval over the socket. Limits are approximate and scoped to each Cloudflare location. [Workers Rate Limiting](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/)
3. **Enforce a daily budget.** Keep an atomic daily counter and one active inference lease per user in a SQLite Durable Object keyed by verified identity. Charge a slot before inference so opening tabs or reconnecting cannot reset the cap. Put an application-level quota in front of inference for a hard account ceiling, or route the model through AI Gateway for a second layer of traffic and spend controls. Surface quota exhaustion in the pane and return control to the player. [Strict Workers limits](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/#strict-limits), [AI Gateway rate limits](https://developers.cloudflare.com/ai-gateway/features/rate-limiting/), [AI Gateway spend limits](https://developers.cloudflare.com/ai-gateway/features/spend-limits/)

Test the budget with multiple tabs, reconnects and overlapping inference requests. Track admitted and blocked requests, model latency and usage. Keep screen frames out of logs and disable request-body logging if AI Gateway is added.
